# Pattern Lens

Сервис для проверки транскрибаций встреч «бодрое утро» (планёрка руководителя точки продаж
малого бизнеса с клиентскими менеджерами) на соответствие фиксированной методологии супервизии
с помощью LLM.

## Возможности

- **Методология супервизии «бодрого утра»** зашита как 6 фиксированных этапов (Новости/релиз ММБ,
  Инфоповоды, Обратная связь от клиентов, Обсуждение вчерашней встречи, Итоги вчерашнего дня, Задачи на
  сегодня), каждый — со своими критериями. По каждому критерию модель выносит вердикт **Да/Нет** с
  пояснением, в каком блоке диалога это обнаружено (или почему не обнаружено). Этапы и их критерии не
  редактируются через UI — это фиксированная методология, см. `app/stages.py`.
- Переключатель провайдера LLM прямо в UI: **GigaChat** (GigaChat-2 / -2-Pro / -2-Max) или
  **OpenRouter** (DeepSeek, Gemini, Claude, GPT, Qwen) — список моделей зависит от выбранного провайдера.
  OpenRouter — внешний сервис: на хостинге без доступа в интернет (например, внутренний контур) будет
  недоступен, работает только GigaChat.
- Каждый выполненный критерий подсвечивается **своим цветом** (по этапу) — сразу видно, где именно в
  тексте сработало условие; легенда над результатом показывает соответствие цвет → этап → сколько раз
  найдено. Клик по подсвеченному фрагменту показывает всплывающее окно с точным объяснением от модели.
- **Итоговое заключение** — короткий текстовый вывод от LLM по всей транскрибации: какие этапы выполнены
  полностью, какие — нет и почему, что стоит улучшить.
- **Экспорт в .doc** — итоговое заключение, чек-лист этапов с критериями, легенда найденных подсветок и
  полный текст с подсветкой выгружаются одним файлом, открывается в Word/LibreOffice.
- **Хранение прогонов на клиенте** — последний прогон анализа (текст + результаты) сохраняется в
  `localStorage` браузера и восстанавливается при обновлении страницы. Приложение не имеет собственной
  базы данных и не хранит ничего на сервере.

## Запуск

```bash
cd pattern-lens
cp .env.example .env   # заполнить GIGACHAT_CREDENTIALS и/или OPENROUTER_API_KEY
uv sync
uv run uvicorn app.main:app --reload
```

Открыть http://localhost:8000

Провайдеры независимы — можно заполнить только один из ключей `.env` и пользоваться только
соответствующим провайдером в переключателе; попытка выбрать провайдер без заполненного ключа
вернёт понятную ошибку в UI, а не 500.

## Как это устроено

- `app/stages.py` — фиксированные этапы методологии супервизии и их критерии (текст, детальное описание
  для модели, правило агрегации этапа: «все критерии» или «любой из»). Часть кода, не хранится в БД, не
  редактируется через UI.
- `app/llm_providers.py` — единая точка вызова LLM с переключателем `provider`/`model`: GigaChat через
  `langchain-gigachat`, OpenRouter — прямой REST-вызов.
- `app/analyzer.py` — формирует промпт из списка этапов+критериев методологии и текста транскрибации,
  просит модель одним вызовом вернуть JSON-объект `{criteria, summary}` (вердикт Да/Нет по каждому
  критерию каждого этапа + итоговое заключение), затем находит каждую цитату в исходном тексте по
  подстроке, чтобы вычислить точные координаты для подсветки на фронте, и агрегирует вердикт этапа
  (`passed`) по правилу агрегации (AND/OR) из `stages.py`.
- `app/static/index.html` — самодостаточный UI (без сборки): textarea + переключатель провайдера/модели +
  summary-блок + легенда подсветок + подсвеченный результат + экспорт в .doc (собирается на фронте) +
  панель этапов (раскрывающиеся карточки со списком критериев и вердиктом Да/Нет). Цвет этапа — из
  приглушённой палитры (`STAGE_PALETTE`, по индексу этапа), стабилен между запусками. Последний прогон
  сохраняется в `localStorage` браузера.

Приложение не имеет базы данных и не хранит транскрибации/результаты на сервере — весь стейт живёт в
браузере пользователя (`localStorage`) на время между запросами к LLM.

## Источник методологии

`БУ_критерии_оценки.xlsx` и `Пояснения для агента Супервизии.pdf` в корне репозитория — исходные
материалы, на основе которых собраны этапы и критерии в `app/stages.py`. При изменении методологии
нужно синхронизировать оба места.
